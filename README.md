# claude-code-company-setup

**会社設立を、AI に「調べさせる」のではなく「検算させる」ための Claude Code Skill。**

合同会社を1社、士業に頼まず自分で設立した記録から起こしました。
定款・登記・法人番号・税務届出（設立届／青色申告承認申請）・法人口座・D-U-N-S まで、
**実際に間違えたことだけ**を型にしてあります。

> A Claude Code skill for incorporating a company in Japan — built to make the AI
> *verify your assumptions against primary sources*, not just answer from memory.

---

## なぜ作ったか

会社設立の情報はネット上に大量にあります。だから調べること自体は難しくない。
難しいのは、**自分が正しいと思い込んでいる箇所ほど調べ直さない**ことです。

実際、3ヶ月で3回止められました。**3回とも「調べる必要がない」と思っていた場所**です。

| # | 思い込んでいたこと | 実際 | 気づかなかったら |
|---|---|---|---|
| 1 | 「県の名前がついた税務署があるんだから、そこだろう」 | 県名と税務署名は無関係。管轄は市区町村（さらに区）で決まる | 管轄外に郵送。受理日がずれる |
| 2 | 設立届に登記事項証明書（謄本）が要る | **平成29年4月1日以後、添付が不要** | 謄本を1通よけいに取得（1通600円＋法務局への往復） |
| 3 | 「いちばん近い期限＝いちばん大事」 | **罰則があるのは実質ゼロ。落とせないのは青色申告承認申請だけ** | 第1期が白色に確定。やり直し不可 |

3がいちばん重い。「近い期限から潰す」は一見正しいのですが、実務では
**「落としたときに取り返せない順」に並べ替えないと事故ります。**

## インストール

```bash
git clone https://github.com/dataanalytics2020/claude-code-company-setup \
  ~/.claude/skills/company-setup
```

Claude Code を再起動すると、会社設立まわりの話題で自動的に呼ばれます。
明示的に呼ぶなら `/company-setup`。

## 使い方

```
合同会社を作ろうと思っています。本店はバーチャルオフィスの予定です。
```

と話しかければ、形態・本店・決算月の3つを確定させるところから始まります。

すぐ使いたい人向けに、**検算プロンプト**だけ置いておきます。

```
【調べること】○○
【条件】
- 根拠は次のドメインの情報だけを使う: nta.go.jp / moj.go.jp / e-gov.go.jp
- 参照したURLを必ず出す
- 制度変更があった場合は「いつから」も書く
- 似た名前の役所・書類がある場合は、なぜそちらではないのかも書く
```

**最後の2行が効きます。**
「いつから」を聞くと、古い情報を根拠にしたときに破綻が出ます。
「なぜそちらではないか」を聞くと、似た名前で間違えるパターンを潰せます。

## 中身

| ファイル | 何が書いてあるか |
|---|---|
| `SKILL.md` | 検算の型・進行の順番・AI が断定してはいけない線引き |
| `references/deadlines.md` | 期限の重みづけ。青色申告承認申請の期限計算と、均等割の誤解 |
| `references/documents.md` | 3系統の提出先・添付書類の要否・記入値をそろえる表 |
| `references/notation.md` | 表記統一。異体字（`栁` `髙` `﨑` …）の二重運用 |
| `references/bank-account.md` | 法人口座。VO × 設立直後は落ちる前提の設計と、落ちたあとの立て直し |
| `references/sources.md` | 一次情報のURL（国税庁・法務省・法務局・e-Gov・年金機構） |
| `scripts/check_notation.py` | 登記簿の表記を基準に、各所の登録内容の表記ゆれを検出する |

### `check_notation.py`

会社設立後、同じ会社情報が10箇所以上に登録されます（法人番号公表サイト・法人口座・
D-U-N-S・Apple・自社サイト・請求書…）。そのどれか1つがズレていると、口座審査で落ちたり、
Apple 側だけ直せなくなったりします。

**自分で入力していない場所のミスは、自分では気づけません。** だから機械的に突き合わせます。

```bash
python3 scripts/check_notation.py --init > company.json
# company.json に登記簿の表記と、各所の実際の登録値を書く
python3 scripts/check_notation.py company.json
```

```
バーチャルオフィス管理画面
    ✗ 不一致 本店
        登記: ○○県△△市□□区…
        実際: ××都△△市□□区…      ← 都道府県だけが違う

法人口座の申込
    ≈ 表記ゆれ ×3（全角/半角・丁目→ハイフン・異体字）
```

全角/半角、丁目・番地の書き方、異体字は「**同じ対象の別表記**」として区別して出します。

## 🔴 免責

このスキルは**手続きの地図と検算の型**を提供するものです。
税務・法務の個別具体的な助言ではありません。

- **税額・税率の具体的な計算と、個別の節税判断はしません**（税理士法の領域です）
- 管轄・様式・期限は**断定せず、一次情報のURLを添えて「確認してください」で返します**
- 制度は変わります。**必ず官公庁のページで最新を確認してください**

記載内容は 2026年9月時点で一次情報に当たって確認したものですが、
その正確性・最新性を保証するものではありません。利用は自己責任でお願いします。
